## 1. 問題、背景與動機

### 問題

重視價值觀與深度交流的成年單身者，缺少能在安全、有引導的情境中探索生活觀、財務觀、人生觀與情緒需求的社交體驗。PDF 以竹科專業人士為示意 Persona，提出工時長、社交圈窄、擔心在小圈子被認出、既有交友場域難深入等問題，並引述竹科聯誼 160 個名額、近 800 人報名等數字。PDF 將來源概括標註為政府統計、新聞及報告，尚未完成逐項書目與數字核查，不作正式已驗證事實。預計訪談 20 位竹科／內湖科技人，該研究尚未完成，相關需求目前仍屬待驗證假設。

### 背景

本網站為《心靈契合：30天，走向彼此》沉浸式體驗與紀實節目 IP 的產品介紹及報名入口，呈現免費線上語音入口、單場城市夜、三種封閉營及三級年度會籍。首版付款方式仍為主辦方確認後聯絡，網站不收款；年度會籍的申請／邀請制度待決。體驗包含語音交流、匿名資源配置情境、情境應變與自主選擇。

正式活動申請、低門檻意向登記及 AI／手動快速申請均須填寫性別並上傳 2 至 6 張照片；照片僅供申請審閱，不公開、不用於節目拍攝，也不傳送至 AI 服務。所有個人資料與照片的保存期限統一為相關活動結束日起 3 年；尚未對應到活動的資料如何設定起算事件，仍待決策。

產品設計原則：先確認基本生活相容，再探索內在價值；以活動體驗與工作坊為交易內容；不承諾配對或關係結果；一般售票場不拍攝，拍攝特別場須另行授權；主辦方與 AI 僅作活動引導，不推薦配對或私下牽線。

### 動機

建立可信、溫暖且資訊完整的雙語入口，說明不同活動階段、申請方式與參與邊界，並收集合格申請供主辦方後續審核與聯絡。

## 1.1 產品定位與產品線：線上入口、單場體驗、封閉營與年度會籍

本版以 PDF 新方案取代 v1.14 的舊四階產品名稱與定價。產品呈現分成三個不同概念，避免把所有產品誤寫成單一必經銷售漏斗：

- **體驗／轉換路徑：** PDF 提案順序為每週免費線上語音樹洞 → 城市樹洞夜 → 三種封閉營 → 年度會籍。年度會籍是可選後續方案／升階，不是每位參與者的必經購買；此漏斗關係依 PDF 描述整理，正式轉換規則待營運確認。免費入口與城市夜的報名欄位、平台、場次及容量仍待定義。
- **年度會籍產品線：** 「樹洞／契合／真實契合黑卡」三種 12 個月方案，作為封閉營後可選的延伸／升階產品；各級權益、資格、服務次數及是否邀請制仍待定。黑卡提案限量 30 席。
- **30 天節目敘事主線：** 免費線上語音與城市樹洞夜是前置入口；封閉營一《心靈樹洞》對應第一幕「聽見」（Day 1–3），封閉營二《共好之間》對應第二幕「看見」（Day 4–10），封閉營三《風起之時》對應第三幕「並肩」（Day 11–17）。前三幕可分開購買。第四幕「選擇」（Day 18–30）是回到真實生活後的自主相處與選擇，不另售為第四款封閉營，也不構成關係結果承諾；PDF 提出以《關係價值觀共識卡》／共識白皮書作為產出。

PDF 提案另含一對一教練、形象顧問、企業包場及節目冠名，先列商業延伸，不納入首版網站交易流程。各價格、供應地點、日期、名額、費用包含項目、資格、會員權益、取消條款及英文譯文上線前須由營運確認；旅遊部分需合作旅行社及法務核定。一般活動不拍攝；自願拍攝特別場另行揭露並授權。

## 1.2 首版轉換路徑與分流

本輪確認首版包含 PDF 新產品線介紹、免費線上語音樹洞與城市樹洞夜入口、封閉營及年度會籍資訊、正式申請、低門檻意向登記、快速申請單一入口（AI 助填／自行填寫）、免費社群介紹與候補通知登記，以及獨立節目海選意向表單。城市夜／免費語音的正式欄位與場次管理方式仍待確認。AI 助填僅在快速申請流程中提供，不再設置獨立免聯絡資料 AI 體驗入口。社群開放前不提供加入連結；海選資格於初步審核後提供詳細資訊與授權流程。

1. **首頁入口分流：** 訪客可探索免費語音、城市樹洞夜、封閉營、年度會籍、社群或節目海選；正式申請只有一個「快速申請」入口，進入後選擇 AI 助填或自行填寫。
2. **快速申請單一入口：** AI 對話助填與自行填寫是同一申請流程內的兩種方式，不另設獨立 AI 體驗頁或 AI 對話導覽入口。從產品／場次詳情進入時沿用已選階段／月份；從首頁進入時先選活動階段。
3. **低門檻意向登記：** 獨立於正式活動申請，收集稱呼、精確年齡、聯絡方式（Email／電話規則待確認）、成年單身聲明、希望參與的產品階段及可複選月份；是否寄送確認通知待確認。意向登記不等同正式申請、錄取或付款。
4. **正式活動申請：** 申請者進入單一「快速申請」入口後，可選 AI 對話逐題整理或自行逐欄填寫。由產品／場次詳情進入時沿用已選階段／月份；由首頁進入時先選階段。基本資料確認後可略過補充資料或選用履歷解析；完成月份與必要聲明後，才於送出前使用 LINE 登入／註冊。Email 必填以寄送確認信，電話選填。詳細資料由申請者確認後才納入申請；學經歷證明可後續補交。
5. **節目海選：** 提供獨立意向表單。初步審核通過後才向申請者提供詳細資格與後續流程；任何節目演出、肖像／聲音與拍攝授權須另行、明確且自願同意。海選資料由授權營運人員查看；本輪選定所有獲授權營運人員可查看全部 CRM 資料，須以稽核軌跡及存取控管降低風險，不得宣稱人員間已實體隔離。
6. **免費社群：** 顯示社群介紹及候補通知登記；社群正式開放後再通知，不在尚未開放時提供加入連結。平台、版主、管理規範及通知方式仍待確認。
7. **後續聯絡與收件：** 網站後台／CRM 接收意向登記與活動申請；主辦方可檢視資料、更新申請／候補狀態並記錄聯絡。正式申請提交後，網站顯示通知並寄送確認信；主辦方確認後另行聯絡付款，網站不收款。涉及旅遊的場次由合作旅行社承辦旅遊部分、主辦方承辦工作坊部分，分別提供契約與費用明細；各自取消／退款條款核定前不開放付款。

### 高信任資訊專區

網站須說明一般活動不進行影像拍攝、封閉營三另設自願拍攝特別場、不同意拍攝不影響一般活動申請；活動錄音依四幕錄音規則另行取得同意。任何「絕對隔離」、「絕對隱私」或資料隔離技術承諾，須有已實作的權限、資料儲存與營運流程作依據後才能發布；不得將尚未落地的設計寫成保證。

## 2. 目標使用者、Persona 與情境

### 主要使用者

主要 Persona 為 25–44 歲高薪科技業單身者，先從竹科／內湖招募；女性專業人士可延伸至醫師、律師、金融、PM、藝文等族群。此為招募方向，不構成財力審核或資格保證。年齡、職業集中度及市場規模仍須透過 PDF 所列 20 位目標使用者訪談驗證。

**PDF 市場規模估算（未獨立核實）：** 以資訊電子製造從業人員約 85 萬為起始參考；TAM 估 21–50 萬科技單身從業者，SAM 估 7.5–10 萬高薪科技單身族群，SOM 估首年約 700 服務人次。PDF 另以竹科約 17.9 萬從業者作灘頭市場依據。以上為 PDF 推估值與推導，需取得可追溯來源、定義口徑與調查結果後才能作正式市場數字或宣傳。

### Persona A：重視深度交流的申請者

- 想透過有引導的活動深入交流價值觀與溝通方式。
- 報名前需要了解活動內容、價格、日期、地點、行程節奏、團隊、隱私與申請規則。
- 不希望被主辦方承諾或安排配對；關係發展由參加者自主決定。

### Persona B：年度會籍潛在參與者

- 希望比較年度方案權益、服務範圍與全年費用。
- 是否採邀請／審核、一般會籍如何申請，需由營運確認；黑卡 30 席為 PDF 提案。

### 關鍵情境

使用者由品牌內容進站，切換中英文，瀏覽免費語音、城市樹洞夜、封閉營與年度會籍，閱讀活動／隱私／申請規則，再依產品入口登記或申請。正式活動申請者勾選必要聲明並完成 LINE 登入，提交後收到畫面通知與確認信；主辦方後續聯絡名額與付款方式。額滿或截止時仍可申請候補，候補由主辦方人工挑選；「截止」代表不再進入一般名額審核，但候補意向仍可收件，除非營運人員關閉該月份收件。

## 3. 目標與衡量方式

### 商業目標

- 以免費線上語音入口與城市樹洞夜建立低門檻體驗路徑，介紹封閉營及年度會籍產品。
- 收集合格正式申請並驗證目標族群的參與與付費意願。
- 以透明活動內容、參與規則及隱私說明建立信任。
- PDF 提出 90 天驗證期；此為商業提案，不是已達成成效或已核定營運承諾。

### 使用者目標

- 快速判斷產品階段、費用、行程與參與條件是否適合自己。
- 知道申請不等同錄取或付款，並理解候補及拍攝規則。
- 知道自己的資料如何使用及預計何時刪除。

### 指標

- **北極星指標：** 合格正式活動申請數。初期只記錄數量，不設定數字目標；意向登記、節目海選、社群候補通知分開計數；正式申請可另按 AI 助填／自行填寫方式拆分觀察，不混入北極星指標。
- **合格正式活動申請定義：** 申請者使用 LINE 登入／註冊，完成稱呼、Email、精確年齡、性別（女性／男性／其他）、2 至 6 張合規照片、活動階段／月份等必填欄位，聲明已成年且目前無婚姻關係，並同意活動安全公約及必要個資告知。電話為選填；職業、學經歷、價值觀與動機均為選填，不影響申請計數；不核實財力或戶籍。
- **建議次要指標（基準／目標待定）：** 免費語音登記與出席數、城市夜／封閉營申請及付費轉換、會籍意向與預售、意向登記數、節目海選申請數、按產品／月份的申請數、產品頁到表單開啟率、表單完成率及候補量。
- **90 天驗證提案（尚未核定／驗證）：** PDF 的 Go 門檻為每場預售達 75% 成團門檻、女性報名占比至少 40%、創始會員至少 6 席、線上至付費轉換至少 10%、隱私事件 0 件。報告實用度至少 4.5／5、NPS 至少 50、30 天回訪／升階至少 25% 為 PDF 提案值；須先定義量測樣本、問卷、分母及資料來源，不得當成現況基準。
- **90 天驗證節奏（PDF 提案，尚未排定）：** Day 1–30 訪談 20 位科技人並辦 4 場線上語音體驗，驗證痛點、願付價格及獲客成本；Day 31–60 預售 2 場城市樹洞夜及第一場封閉營，驗證出發前 21 天收款與 75% 成團條件；Day 61–90 預售創始會員，並驗證會員預付意願及款項保管方案。每階段樣本、活動日期、預算、負責人及停止／調整條件待定。
- **護欄指標（基準／目標待定）：** 申請者取消／申訴數、未經授權拍攝或資料存取事件、刪除逾期事件、錯誤候補／場次狀態。

## 4. 範圍與 User Stories（MoSCoW）

### Must

1. 身為訪客，我想瀏覽免費語音入口、城市樹洞夜、封閉營與年度會籍產品資訊，以便比較體驗方式、價格與參與邊界。
2. 身為體驗申請者，我想查閱單場、封閉營及會籍的價格、場次狀態、地點與行程資訊，以便評估參與方式。
3. 身為活動申請者，我想選擇 AI 對話或逐欄自行填寫，分步確認資料並在送出前完成 LINE 登入，以便快速完成且保有編輯權。
4. 身為申請者，我想在提交後看到成功通知並收到確認信，以便知道申請已送達、等待主辦方聯絡。
5. 身為候補申請者，我想在場次頁看見候補狀態並提交申請，以便由主辦方評估候補名額。
6. 身為年度會籍潛在參與者，我想比較年度產品的權益及費用，並知道各級申請方式，以便向主辦方了解下一步；實際資格與流程待營運確認。
7. 身為活動申請者，我想在單一快速申請入口中選擇 AI 助填或自行填寫，以便用適合自己的方式完成資料；不提供獨立免聯絡資料 AI 體驗頁。
8. 身為訪客，我想了解免費語音樹洞與社群並登記場次／開放通知，以便先參與或在服務開放時收到消息；平台、開放方式與資料欄位待定。
9. 身為有興趣的訪客，我想先提交低門檻意向登記，以便表達想參與的階段與月份，再由主辦方聯絡。

2. 申請者選擇「AI 對話」或「自行填寫」。AI 路徑逐題詢問稱呼與精確年齡、Email／選填電話、參與期待；手動路徑一次呈現一個欄位，逐步完成稱呼、年齡、Email、電話（選填）。
3. AI 將已辨識資料及參與期待整理成可編輯欄位／短標籤。無法辨識的必填欄位提示補填，保留其餘資料；申請者可刪除任何 AI 期待標籤，刪除內容不納入申請。
4. 申請者檢視並編輯稱呼、有效 Email、精確年齡及選填電話。基本資料確認後，可略過補充資料，或選擇手動補充職業、學經歷、價值觀／參與期待，也可選用履歷解析。學經歷及價值觀／參與動機先以標籤選項呈現，每個區塊最下方才提供選填自由文字欄；兩者均不得設為必填。
5. AI 與手動模式皆進入共用個人資料確認步驟：必選性別（女性／男性／其他），並上傳 2 至 6 張 JPG／PNG／WebP 照片，每張不超過 10MB。照片只供申請審閱，不公開、不用於節目拍攝或 AI 處理。
6. 履歷解析須在同意後進行；解析欄位以草稿顯示並由申請者確認才納入申請。履歷與其他個人資料於相關活動結束日起保存 3 年；解析失敗可改手動填寫或略過。
7. 申請者選擇一個或多個可申請月份，確認成年單身聲明、安全公約與個資告知同意。額滿或截止月份均顯示候補並可提交候補申請；候補由主辦方人工挑選，營運人員可關閉該月份收件。
8. 送出前完成 LINE 登入／註冊。登入成功後檢查必填資料、性別、照片與聲明；若驗證失敗，標示錯誤欄位並保留所有已填內容。
9. 驗證成功後建立正式申請、顯示成功／候補結果並寄送 Email 確認信。原型僅模擬結果，不連接 LINE、AI、履歷解析、寄信或資料儲存服務。

### 其他首版路徑流程

1. 訪客進入首頁後可瀏覽產品、免費社群或節目海選；正式申請統一由「快速申請」入口開始。
2. 申請者進入快速申請後，選擇 AI 對話助填或自行逐欄填寫；兩種方式均屬同一正式申請流程。
3. AI 助填依序整理稱呼／年齡、聯絡方式與參與期待；基本資料由申請者確認，期待整理為可編輯且可刪除的短標籤。確認納入的欄位隨正式申請一併送出；不另存 AI 對話逐字稿。
4. AI 助填僅協助整理申請者輸入，不作心理診斷、配對推薦、相容度判定或資格決定；相關規則已併入快速申請主流程。
5. 訪客可提交低門檻意向登記，選擇一種或多種參與階段及可參與月份；網站後台／CRM 保存登記，主辦方人工聯絡。
6. 訪客可依已開放產品提交申請或意向；城市樹洞夜、封閉營以場次／月份設定名額，實際日期及正式申請欄位待營運核定。
7. 節目海選者先提交獨立意向表單；初步審核後才提供詳細資格與後續授權資訊。意向送出不構成拍攝授權。
8. 免費線上語音樹洞為新確認的產品入口；正式場次的報名方式、平台及人數管理待營運確認。在正式開放前可提供意向／通知入口，但不得把尚未落地的每週場次描述成已可使用。免費社群仍提供介紹與候補通知；開放前不提供加入連結。

節目海選流程必須與私密活動資料及申請名單分開處理。任何拍攝邀請、肖像／聲音／演出授權都需獨立、清楚、可拒絕，不得以申請私密活動作為授權條件。

## 7.1 後續階段：會員中心與營運後台規劃（非首版範圍）

本章記錄長期服務交付與內部營運需求，供後續產品階段估算。它不改變首版「單場活動申請、主辦方確認後聯絡付款」的範圍，也不代表已確認提供婚姻媒合或持續性會員服務。若會員中心要承接 30 天或更長期的服務，須先確認服務交付物、期限、費用／契約、個資用途、退出／刪除規則，並重新檢視產品定位及履約方式。

### 會員中心（參加者視角）—後續候選功能

- **個人報告區：** 會員可查看已完成活動的個人溝通模式分析或 AI 對話復盤報告，查看時間、版本與下載／刪除方式。
- **報告內容邊界：** 「三觀契合度雷達圖」、「潛在價值觀衝突提示」與「下次聊天建議提問」屬新增概念，須先驗證資料來源、演算法方法與表述依據。避免將內容描述為心理診斷、客觀相容度判定、他人評分或配對推薦；報告應區分自我反思與事實，允許會員更正脈絡或提出刪除要求。
- **活動行事曆：** 顯示已報名場次、活動須知與狀態。線上預約、候補、取消／退出、請假及改期作業屬後台整合需求，須先確認各產品實際提供哪些服務、取消政策與退款規則。
- **會員資料控制：** 顯示資料用途、已同意項目與同意時間；提供更正、撤回可選同意及聯絡資料刪除／申請入口。會員不能查看其他參加者的私密資料或報告。

### 顧問與節目組後台（內部視角）—後續候選功能

- **角色與稽核：** 本輪首版決策為所有獲授權營運人員可查看全部 CRM 資料，包含海選意向。須記錄登入與資料檢視／匯出／修改／刪除操作，並明確揭露此權限配置的隱私風險；未來如改採最小權限，再建立角色分權方案。
- **擴充型活動 CRM：** 會員生命週期、活動履約、參加須知確認、報告交付及多角色營運流程屬後續候選功能。首版僅納入申請收件檢視、申請／候補狀態更新與聯絡紀錄，不包含本段所述完整 CRM。
- **節目海選資料分流：** 海選意向與一般活動申請須在用途與同意紀錄上區分；本輪決定授權營運人員可查看全部 CRM 資料，因此目前不是人員權限隔離。資料庫／部署隔離強度、存取稽核、備份、金鑰與管理權限仍待技術評估，未落實前不得宣稱物理隔離或絕對隔離。
- **互斥條件處理：** 原提案提出依生育意願、宗教、負債上限等 Deal-breakers 自動過濾並由顧問覆核。此功能涉及高度私密資料，也可能構成自動化篩選／媒合，與目前不做推薦配對、只賣活動體驗的原則衝突，故列為**暫不納入**。若日後重新提出，須先確認合法用途、最少蒐集、明確同意、可解釋規則、人工覆核、申訴／更正及不以演算法決定參加資格；不得直接套用到活動申請者。
- **營運狀態燈號：** 可追蹤申請已收件、場次確認、契約已提供／審閱、付款聯絡／核銷、活動完成與報告交付等狀態。狀態須限於營運必要資料，避免把「單身驗證」或「財力驗證」列為標準流程；目前原則是不核實婚姻狀態、財力或戶籍。學經歷證明於後續補交；收件與人工檢視規則待定。合約審閱期與付款核銷的期限及責任角色待定。

### 例外處理

- 欄位缺漏或格式錯誤：標示具體欄位並保留已填內容。
- 送出失敗：告知未完成，不顯示成功；提供重試或聯絡方式，避免重複申請造成誤解。
- 郵件寄送失敗：申請仍保留；畫面提示申請已收到但確認信可能延遲，提供主辦方聯絡方式（需提供）。
- LINE 登入失敗／取消：保留尚未送出的表單資料，提供重試或返回修改；未完成登入驗證前不得建立正式申請。
- 履歷解析／上傳失敗：保留已填必填欄位並允許重試或直接略過，申請者仍可送出；不得將履歷上傳或解析設為申請門檻。
- 額滿／截止：標示候補，不承諾遞補；仍可申請，由主辦方人工挑選。
- 年度會籍：顯示各級申請方式；黑卡是否邀請／審核制待確認，不提供未核定的一般申請表。
- 場次取消或變更：網站顯示更新及聯絡／取消安排；具體退款與通知政策待核定。

## 8. Must 驗收條件（Given／When／Then）

### Story 1：雙語產品介紹

- **Given** 訪客進入網站，**When** 選擇中文或英文，**Then** 主要導覽、產品資訊、表單標籤、同意文字與通知內容均以所選語言呈現。
- **Given** 新產品資訊與價格已由主辦方核准，**When** 訪客瀏覽產品總表，**Then** 可分辨免費入口、城市夜、三種封閉營及三級年度會籍，並查看費用、形式、時程與申請方式；年度會籍不被呈現為體驗漏斗的必經階段。

### Story 2：場次資訊與候補

- **Given** 主辦方公布月份名額，**When** 訪客檢視活動，**Then** 頁面顯示開放月份、名額狀態、縣市／區域、費用及申請入口；實際日期標示為後續確認。
- **Given** 場次為額滿或截止狀態，**When** 訪客檢視該場次，**Then** 頁面明確標示候補且仍提供申請入口，並說明由主辦方人工挑選、不保證遞補。

### Story 3：漸進式快速申請

- **Given** 訪客從產品／場次詳情啟動申請，**When** 進入快速申請，**Then** 沿用已選階段／月份並提供 AI 對話與自行填寫兩種入口。
- **Given** 訪客從首頁啟動申請，**When** 尚未選活動階段，**Then** 系統先要求選擇可申請階段，再進入填寫方式選擇。
- **Given** 申請者選擇 AI 對話，**When** 逐題回答或略過參與期待題，**Then** 系統整理可辨識欄位並進入可編輯確認畫面；辨識不到稱呼、年齡或 Email 時，只提示補填缺少欄位並保留其他資料。
- **Given** 申請者選擇自行填寫，**When** 逐欄完成稱呼、年齡、Email、電話，**Then** 每一步只呈現目前欄位，電話可略過，並可返回修改。
- **Given** 申請者完成基本資料，**When** 進入補充資料步驟，**Then** 可略過、手動補充或選用履歷解析，不因此阻止後續必填申請。
- **Given** 申請者展開學經歷或價值觀／參與動機，**When** 填寫補充欄位，**Then** 先顯示標籤選項，區塊最下方提供選填自由文字欄；不選標籤、不輸入文字或整段略過皆可繼續申請，欄位不得標示必填。
- **Given** 必填資料、可申請月份及必要聲明均有效，**When** 申請者於送出前完成 LINE 登入並送出，**Then** 顯示成功／候補結果並寄送 Email 確認信；驗證或登入失敗時標示錯誤且保留已填資料。

### Story 4：成功通知與確認信

- **Given** 申請成功保存，**When** 系統完成提交，**Then** 顯示成功訊息並寄出申請確認信，內容說明申請已收到、尚待主辦方確認與後續付款聯絡。
- **Given** 郵件服務暫時失敗但申請已保存，**When** 顯示結果，**Then** 不宣稱郵件已寄達，並提供聯絡方式或稍後重寄資訊。

### Story 5：候補人工處理

- **Given** 申請者申請額滿／截止場次，**When** 提交成功，**Then** 成功畫面與確認信均標示候補狀態，並說明由主辦方人工挑選。

### Story 6：AI 對話與申請欄位帶入

- **Given** 申請者選擇 AI 對話，**When** 依序回答基本資料、聯絡方式及參與期待三組問題，**Then** 每次只顯示一題並可返回、略過可選問題或繼續。
- **Given** AI 可辨識回答內容，**When** 整理完成，**Then** 稱呼、年齡、Email、電話及參與期待出現在可編輯確認欄位／短標籤中，等待申請者確認。
- **Given** AI 無法辨識必填欄位，**When** 顯示整理結果，**Then** 明確指出需補填的欄位並保留其餘已辨識內容，不要求整段重答。
- **Given** AI 產生參與期待短標籤，**When** 申請者按下該標籤的「×」，**Then** 該內容從本次申請草稿移除且不納入送出的申請資料。
- **Given** AI 對話尚未送出申請，**When** 申請者離開流程，**Then** 不建立申請且不保存原始逐字稿或未確認草稿；送出後僅保存申請者確認納入的欄位。
- **Given** 任何 AI 整理結果，**When** 顯示給申請者，**Then** 不包含分數、相容性判定、對象推薦或資格決定。

### Story 7：意向登記與獨立路徑

- **Given** 訪客選擇意向登記，**When** 填寫表單，**Then** 可提供稱呼、精確年齡、成年單身聲明、希望參與階段與可複選月份，並依核准規則提供聯絡方式及看到用途告知與必要同意。
- **Given** 節目海選資格尚未公開，**When** 訪客提交海選意向，**Then** 使用獨立表單收件，並告知初步審核後才提供詳細資格；送出意向不構成拍攝授權。

### Story 8：月度選擇與 CRM 處理

- **Given** 主辦方已公布月度活動名額，**When** 訪客填寫意向登記或正式申請，**Then** 可選擇一個或多個開放月份；活動詳細日期標示為後續確認。
- **Given** 主辦方設定月份名額及截止狀態，**When** 訪客查看場次，**Then** 前台僅顯示「可申請／候補／截止」，不公開精確名額數。
- **Given** 新意向登記或正式申請送出成功，**When** 授權營運人員登入後台，**Then** 可檢視該筆資料、更新申請／候補狀態並新增聯絡紀錄。
- **Given** 免費社群尚未開放，**When** 訪客查看社群區，**Then** 可登記候補通知，且不會看到尚未核准的加入連結。

### Story 9：LINE 快速申請與選用履歷解析

- **Given** 申請者已填必填資料並完成月份及聲明，**When** 準備正式送出，**Then** 系統才要求 LINE 登入／註冊；登入失敗時保留表單資料並提供重試。
- **Given** 申請者選用履歷解析，**When** 選取 PDF／DOCX 且檔案不超過 10MB、同意解析並啟動解析，**Then** 系統顯示可編輯草稿並等待申請者確認後才帶入申請欄位。
- **Given** 履歷解析失敗、檔案格式不支援或超過 10MB，**When** 系統回報錯誤，**Then** 已填資料仍保留，申請者可改用手動輸入或略過補充資料。
- **Given** 原始履歷已上傳，**When** 保存期限計算，**Then** 以相關活動結束日起算 3 年後刪除；若資料未對應活動，起算事件待決；履歷解析服務商與資料處理地點仍屬待確認事項。

### Story 10：性別與照片必填

- **Given** 申請者使用正式申請、意向登記或 AI／手動快速申請，**When** 填寫基本資料，**Then** 性別必選女性／男性／其他，且照片須上傳 2 至 6 張。
- **Given** 申請者選擇照片，**When** 檔案為 JPG／PNG／WebP 且每張不超過 10MB，**Then** 可預覽、移除或替換；照片只供申請審閱，不公開、不供節目拍攝或 AI 使用。
- **Given** 照片不足 2 張、超過 6 張、格式不符或單張超過 10MB，**When** 嘗試送出，**Then** 顯示欄位錯誤並阻擋送出，同時保留其他資料並允許移除／替換照片。
- **Given** 使用者提交資料，**When** 保存期限到期，**Then** 個人資料、履歷及照片於相關活動結束日起 3 年刪除；無法對應活動的資料不得套用未確認的起算方式。

### Story 11：免費語音與城市樹洞夜入口

- **Given** 訪客瀏覽產品，**When** 查看免費語音樹洞或城市樹洞夜，**Then** 能辨識免費／付費形式、目前開放狀態與下一步；未確認的場次、平台或容量不得虛構。
- **Given** 城市夜場次已由營運發布，**When** 訪客申請，**Then** 顯示核定後價格（PDF 建議 NT$8,800／人）、時長、地區、費用包含項目及取消規則，並進入已核定的申請路徑。

### Story 12：四幕與封閉營產品對應

- **Given** 訪客查看產品資訊，**When** 比較產品，**Then** 網站呈現免費語音 → 城市夜 → 封閉營 → 可選年度會籍的產品路徑，並清楚標示封閉營一／二／三分別對應「聽見／看見／並肩」前三幕，會籍為自願延伸／升階而非必要條件。
- **Given** 訪客查看 30 天體驗，**When** 閱讀第四幕「選擇」，**Then** 知道這是 Day 18–30 的自主相處階段，沒有第四款封閉營或配對結果承諾；共識卡的實際交付方式依核定資訊展示。
- **Given** 封閉營與前三幕的對應已確認，但年度會籍資格／權益、第四幕共識卡交付方式仍待定，**When** 網站輸出內容，**Then** 明確呈現已確認的幕次對應，不將待確認權益或交付方式描述為已確定服務。

### Story 13：活動錄音同意與使用界線

- **Given** 參加者將報名四幕活動，**When** 報名前閱讀錄音告知，**Then** 明確說明錄音用途為 AI 個人報告與品質檢視、指定人員可存取、活動結束後 3 年刪除，且不作節目素材，並取得明確同意。
- **Given** 參加者未同意錄音，**When** 報名流程處理，**Then** 依核定政策提供替代參與方式或清楚說明該場不適用；替代政策未定前不開放該場報名。
- **Given** 活動錄音完成，**When** AI／品質流程處理音檔或逐字稿，**Then** 遵守已核定的服務商、暫存與刪除政策；政策未定前不得傳送真實錄音。

## 9. 系統限制、風險與緩解

### AI 助填、履歷解析與活動錄音服務（申請助填／履歷方向已選 OpenAI API；語音服務與資料條件待決）

目前選定 OpenAI API 作為繁體中文三題式 AI 助填與選用履歷欄位擷取的服務方向；不需要 AI 評分、推薦或自動決策。可先評估 Responses API 直接接收 PDF／DOCX 檔案並輸出學經歷／職業欄位草稿，所有結果由申請者檢視確認。此為供應商方向選擇，不代表資料處理地點、留存設定、法務核准或跨境處理條件均已確認。

| 方案 | 決策 | 說明 |
|---|---|---|
| **OpenAI API（Responses API）** | **已選** | 官方 API 文件列出 PDF 與 DOCX 為支援的檔案輸入；PDF 可一併處理擷取文字與頁面影像，DOCX 擷取文字。適用於 AI 對話助填與履歷欄位草稿整理。商務 API 輸入／輸出預設不拿來訓練模型。 |
| Azure OpenAI + Document Intelligence | 未選，保留作替代 | 繁體中文文件支援較明確，若 OpenAI API 的驗證或資料條件不合需求，可另行評估；目前不作首版依賴。 |
| Google Vertex AI + Document AI／Cloud Vision | 未選，保留作替代 | 可組合生成式模型與 OCR，但各處理器語言、區域與留存需分別核對；目前不作首版依賴。 |

**實作與資料處理要求：** 首版以 OpenAI Responses API 評估文字對話及履歷解析；應避免啟用不必要的狀態保存，並優先以直接檔案輸入方式處理，避免另行長期存放服務商 Files API 副本。OpenAI 官方資料控制文件說明：Responses API 在部分使用方式下預設可保存應用狀態 30 天，API 濫用監控記錄通常最多保留 30 天；Zero Data Retention 僅適用於符合資格並完成設定的組織／端點。不得在尚未確認帳戶資格、端點行為及合約前承諾零留存或特定資料區域。原始履歷與其他個人資料在本網站依相關活動結束日起保存 3 年；供應商處理副本另依 API 設定與核准條款管理。

**其他尚待確認：** 模型／端點版本、Responses API 設定、使用區域及跨境傳輸、濫用監控／留存、組織是否符合 Zero Data Retention、資料處理附約、子處理者、人工存取與事件通報。未完成個資告知及法務／隱私審查前，不傳送真實申請者履歷或其他可識別資料；概念驗證僅使用合成或去識別樣本。

**官方文件：** [OpenAI API 檔案輸入（PDF／DOCX）](https://developers.openai.com/api/docs/guides/file-inputs)、[OpenAI API 資料控制與留存](https://developers.openai.com/api/docs/guides/your-data)、[Azure Document Intelligence 語言支援](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/language-support)、[Google Document AI 處理器清單](https://docs.cloud.google.com/document-ai/docs/processors-list)。
