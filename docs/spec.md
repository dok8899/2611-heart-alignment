# 《心靈契合：30天，走向彼此》網站功能規格

- 版本：1.1
- 狀態：依 `docs/prd.md` 撰寫；開發前須完成「待定事項」中的阻擋決策。
- 產品範圍：首版雙語公開網站、四階產品內容、前三階活動申請與確認通知。
- 技術棧：React、Python API、SQLite。
- 語言：繁體中文、英文。

## 1. 功能概述／目標

### 1.1 問題

重視價值觀深度交流的潛在參加者，需要在申請前理解四階產品差異、活動費用、國內／海外場安排、團隊配置、場次狀態與隱私規則。主辦方需要收到前三階申請，後續人工聯絡確認與付款。

### 1.2 目標

- 以繁體中文及英文呈現四階產品；價格、地點、行程及團隊內容須可由營運核准後發布。
- 讓前三階訪客提交活動申請，第四階僅呈現邀請制資訊及聯絡入口。
- 額滿／截止場次仍可收候補申請，明確告知候補由主辦方人工挑選。
- 申請成功後顯示成功狀態並寄出自動確認信；網站不收款、不保證錄取或配對。
- 收集與申請處理必要的資料，依核定的告知與期限管理，暫定活動結束後 180 天刪除。

### 1.3 非目標

- 線上付款、退款、電子票券、發票開立。
- 自動錄取、候補排序、配對、推薦、交往追蹤或牽線。
- 身分／婚姻／財力／戶籍／職業驗證。學經歷佐證文件不在首次申請上傳；後續補件流程尚未規劃。
- 登入會員中心、AI 對話復盤報告、線上盲聊、活動請假／改期、CRM。
- 節目海選報名或拍攝授權管理。
- 免費社群及 Lead Magnet AI 體驗。以上均屬 PRD 後續探索或規劃階段。

## 2. 使用情境／使用者故事

### 2.1 使用者

- **訪客／潛在申請者：** 想了解活動與費用，選擇前三階之一並提交申請。
- **候補申請者：** 所選場次額滿或截止，仍提交申請等待主辦方人工評估。
- **第四階受邀對象：** 查閱年度俱樂部資訊，透過聯絡入口洽詢，不提交公開申請表。
- **營運人員：** 維護產品／場次內容，透過指定收件管道接收申請並人工聯繫。首版不提供營運後台。

### 2.2 使用者故事

1. 身為訪客，我想切換繁體中文與英文並比較四階產品，以便理解產品差異與費用。
2. 身為前三階申請者，我想查詢場次日期、地點、行程、價格和狀態，以便評估是否申請。
3. 身為申請者，我想填寫聯絡與活動相關資料、閱讀聲明並送出，以便讓主辦方處理申請。
4. 身為申請者，我想在送出後取得畫面及電子郵件回覆，以便確認系統已收到申請。
5. 身為候補申請者，我想知道自己提交的是候補申請，以便理解後續由主辦方人工聯繫且不保證遞補。
6. 身為第四階受邀對象，我想查看會籍內容並找到聯絡方式，以便了解邀請與審核流程。

## 3. 功能需求

### 3.1 公開網站與內容

FR-001. 網站必須提供繁體中文與英文版本，包含導覽、四階產品內容、表單、錯誤訊息、聲明、成功畫面及電子郵件模板。

FR-002. 網站必須按第一階至第四階順序展示以下產品規劃：

| 階段 | 名稱 | 地點／行程 | 建議價格 | 團隊 |
|---|---|---|---:|---|
| 第一階：入門篩選局 | 《心靈樹洞》AI 盲聊秘境微旅 | 國內：宜蘭礁溪、苗栗泰安、日月潭；3 天 2 夜，週五 19:00 進駐、週日 18:00 賦歸 | NT$48,000／人 | 5 人：主理人、心理引導師、AI 系統工程師、2 位場務管家 |
| 第二階：深度工作坊 | 「共好之間」資源配置與價值觀沙龍 | 國內：花蓮瑞穗、台東池上；海外選配：日本輕井澤或沖繩；核心 7 日、建議請假 5 天 | 國內 NT$128,000；海外 NT$168,000 | 6 人：主理人、2 位心理／行為經濟顧問、AI 工程師、2 位隨團領隊管家 |
| 第三階：旗艦沉浸營 | 「風起之時」莊園共居與情境應變實驗 | 國內：清境／阿里山／陽明山；海外年度場：北海道二世谷；核心 7 日、建議請假 5 天 | 國內 NT$198,000；海外 NT$268,000 | 8 人：製作統籌、心理專家、財務顧問、AI 工程師、2 位管家、2 位紀實攝影 |
| 第四階：年度俱樂部 | 《真實契合》創始黑卡實驗室會籍 | 台北／新竹及國內外莊園；全年彈性預約，含 2 場國內 3 日微旅、1 場國內 7 日沙龍、4 場城市閉門晚宴、全年 AI 系統 | NT$368,000／年 | 專屬關係教練、AI 數據工程師、私人禮賓秘書 |

以上為建議規劃資料。日期、名額、費用包含項目、交通住宿、稅費、退款與契約文字未核准前，不得顯示成已確認供應承諾。

FR-003. 第四階必須標示「限量 30 席、邀請與審核制」，提供主辦方聯絡 CTA，不顯示一般申請按鈕。

FR-004. 第三階團隊含紀實攝影，但 PRD 同時定義一般活動零攝影；拍攝規則核准前，頁面必須避免宣稱第三階已確定拍攝或保證完全不拍攝，並不得開放未決的拍攝授權。

FR-005. 頁面須說明活動體驗不保證配對或關係結果，主辦方及 AI 不提供一對一推薦或私下牽線。

FR-006. 海外活動涉及旅行社、收費主體、保險與契約的公開說明，僅在營運及法務核准後發布。

### 3.2 場次與申請

FR-010. 只有第一至第三階可提交一般申請；第四階導向聯絡方式。

FR-011. 場次狀態至少支援 `OPEN`（開放）、`WAITLIST`（額滿候補／截止候補）、`CLOSED`（關閉不收件）。PRD 要求額滿或截止仍收候補，因此管理內容時應將這兩種狀況設為 `WAITLIST`，而不是 `CLOSED`。

FR-012. `OPEN` 場次表單按一般申請處理；`WAITLIST` 場次可提交但申請狀態標為候補。伺服器端必須重新讀取目前狀態，不可只信任前端傳入狀態。

FR-013. 申請欄位至少包含：姓名、電子郵件、電話或其他核准聯絡方式、精確年齡（整數歲）、場次、職業類別、完整學經歷自填欄位、價值觀／參與動機簡答。學經歷證明文件於後續階段補交，不屬首次申請表上傳項目。

FR-014. 申請者必須勾選成年且目前無婚姻關係之誠信聲明、安全公約同意及個資蒐集告知確認。聲明只記錄使用者自我聲明，不代表主辦方驗證。

FR-015. 不得要求或收集財力、資產負債、戶籍證明；不得將職業用於核驗、錄取或自動排序。職業只作分組參考。申請者先填寫完整學經歷，佐證文件後續補交；補件方式、期限、人工檢視責任人及結果如何使用待確認，未定案前不得作自動篩選。

FR-016. 必填欄位缺漏、格式不符或必要聲明未勾選時，拒絕建立申請，回傳可定位欄位的錯誤。

FR-017. 成功建立申請後，系統須回傳申請編號及申請狀態，前端顯示成功頁並排程寄送確認信。確認信須說明「申請已收到、尚待主辦方確認、網站未收款」。候補申請須明示候補且不保證遞補。

FR-018. 申請保存成功但寄信失敗時，不得回滾申請；記錄寄信失敗狀態供營運重試，前端仍顯示申請已收到並說明確認信可能延遲。

FR-019. 系統不得在前端或 API 對申請者承諾錄取、付款完成、候補順位或配對結果。

FR-020. 申請資料預定活動結束後 180 天刪除。未成行、多場申請、取消、爭議或法令保存例外的起算點尚未定義，資料刪除排程不得在該政策核准前視為完成。

### 3.3 安全與可用性需求

FR-030. SQLite 檔案不得置於公開靜態目錄；生產環境須限制作業系統檔案權限並加密備份。若採用多副本／多主機部署，需重新評估 SQLite 是否符合併發與可用性需求。

FR-031. API 不得在錯誤回應、日誌或分析事件中輸出完整電話、電子郵件、申請動機或其他表單內容。

FR-032. 必須使用參數化 SQL、伺服器端欄位驗證、請求大小限制及基本速率限制，防止注入、垃圾申請與濫用。

FR-033. 訪客不得透過公開 API 查詢或修改已提交申請；首版不提供申請者帳號或查詢申請狀態功能。

FR-034. 前端須支援鍵盤操作、語意化標籤、欄位錯誤提示及行動裝置版面。

## 4. 資料模型

使用 SQLite；所有時間以 UTC ISO-8601 儲存，API 對外回傳 ISO-8601 含時區字串。資料庫主鍵使用 UUID 字串或由應用程式生成的不可猜測 ID。欄位型別為 SQLite 常見型別；外鍵約束必須啟用。

### 4.1 `products`

公開產品階段資料。內容可先以程式內靜態設定或資料庫種子資料提供；若未建管理後台，不允許公開 API 修改。

| 欄位 | 型別 | 規則 |
|---|---|---|
| `id` | TEXT | PK，例如 `tier-1` 至 `tier-4` |
| `tier` | INTEGER | 唯一，1–4 |
| `slug` | TEXT | 唯一、URL 安全 |
| `title_zh` | TEXT | 繁中標題 |
| `title_en` | TEXT | 英文標題；發布前必填 |
| `description_zh` | TEXT | 繁中介紹 |
| `description_en` | TEXT | 英文介紹 |
| `is_public` | INTEGER | 0/1 |
| `application_mode` | TEXT | `PUBLIC` 或 `INVITATION_ONLY` |
| `created_at` | TEXT | ISO-8601 |
| `updated_at` | TEXT | ISO-8601 |

### 4.2 `product_offerings`

同一階產品的國內／海外售價及場地版本。

| 欄位 | 型別 | 規則 |
|---|---|---|
| `id` | TEXT | PK |
| `product_id` | TEXT | FK → `products.id` |
| `offering_code` | TEXT | 例如 `DOMESTIC`、`OVERSEAS`、`ANNUAL` |
| `name_zh` / `name_en` | TEXT | 名稱 |
| `location_zh` / `location_en` | TEXT | 地點描述 |
| `duration_days` | INTEGER | 可為 NULL（年度制） |
| `price_twd` | INTEGER | 新台幣整數；非負 |
| `price_unit` | TEXT | `PER_PERSON` 或 `PER_YEAR` |
| `price_note_zh` / `price_note_en` | TEXT | 包含項目／注意事項，核准後發布 |
| `team_size` | INTEGER | 可為 NULL |
| `team_description_zh` / `team_description_en` | TEXT | 團隊角色描述 |
| `is_published` | INTEGER | 0/1 |

### 4.3 `sessions`

可申請的具體場次。只有對外核准且日期／費用明確的場次可發布。

| 欄位 | 型別 | 規則 |
|---|---|---|
| `id` | TEXT | PK |
| `product_id` | TEXT | FK → `products.id`；僅 1–3 可接受公開申請 |
| `offering_id` | TEXT | FK → `product_offerings.id` |
| `starts_at` | TEXT | ISO-8601；未排期可 NULL、不得公開申請 |
| `ends_at` | TEXT | ISO-8601；未排期可 NULL |
| `location_zh` / `location_en` | TEXT | 場次實際地點 |
| `price_twd` | INTEGER | 此場核准價，可覆蓋產品建議價 |
| `capacity` | INTEGER | 可 NULL；非負 |
| `status` | TEXT | `OPEN`、`WAITLIST`、`CLOSED`、`CANCELLED` |
| `published_at` | TEXT | ISO-8601，可 NULL |
| `created_at` / `updated_at` | TEXT | ISO-8601 |

### 4.4 `applications`

| 欄位 | 型別 | 規則 |
|---|---|---|
| `id` | TEXT | PK，不可猜測 |
| `session_id` | TEXT | FK → `sessions.id` |
| `full_name` | TEXT | 必填，長度上限 120 |
| `email` | TEXT | 必填，格式驗證；大小寫正規化 |
| `phone` | TEXT | 依核准聯絡方式政策必填或選填 |
| `age_years` | INTEGER | 精確年齡（整數歲）；須與成年誠信聲明一致 |
| `occupation_category` | TEXT | 選填／必填性待確認；僅分組參考 |
| `education_text` | TEXT | 完整學經歷自填內容；提交時必填，長度限制待定 |
| `motivation` | TEXT | 價值觀／參與動機簡答；長度上限 3,000 |
| `adult_single_declaration` | INTEGER | 必須為 1 才可提交 |
| `safety_policy_accepted` | INTEGER | 必須為 1 才可提交 |
| `privacy_notice_version` | TEXT | 必填，記錄當時告知版本 |
| `status` | TEXT | `RECEIVED` 或 `WAITLIST`；後續人工狀態不屬首版 API |
| `locale` | TEXT | `zh-TW` 或 `en` |
| `created_at` | TEXT | ISO-8601 |
| `scheduled_deletion_at` | TEXT | 活動結束後 180 天計算；未決例外需政策確認 |

禁止欄位：收入、資產、負債、戶籍證明內容、財力驗證結果、婚姻驗證結果、配對分數、Deal-breakers。初次申請 API 不接收學經歷證明檔案；後續補件端點及檔案儲存規格待定。

### 4.5 `consent_records`

| 欄位 | 型別 | 規則 |
|---|---|---|
| `id` | TEXT | PK |
| `application_id` | TEXT | FK → `applications.id` |
| `consent_type` | TEXT | `ADULT_SINGLE`、`SAFETY_POLICY`、`PRIVACY_NOTICE` |
| `document_version` | TEXT | 同意文字版本 |
| `accepted` | INTEGER | 1 |
| `accepted_at` | TEXT | ISO-8601 |

### 4.6 `email_outbox`

可靠寄信佇列，避免申請保存與寄信服務故障造成不一致。

| 欄位 | 型別 | 規則 |
|---|---|---|
| `id` | TEXT | PK |
| `application_id` | TEXT | FK → `applications.id` |
| `template_key` | TEXT | `APPLICATION_RECEIVED` 或 `WAITLIST_RECEIVED` |
| `recipient_email` | TEXT | 個資；受限存取 |
| `status` | TEXT | `PENDING`、`SENT`、`FAILED` |
| `attempt_count` | INTEGER | 非負 |
| `last_error_code` | TEXT | 不含 PII 的錯誤代碼，可 NULL |
| `created_at` / `sent_at` | TEXT | ISO-8601 |

### 4.7 刪除與資料生命週期

- 申請記錄刪除時，依核准保留政策刪除或去識別化申請資料、同意紀錄與 outbox 收件資訊；合法必須保留的最小交易紀錄需另行定義。
- 不將原始申請內容複製到一般應用日誌、錯誤追蹤或分析平台。
- SQLite WAL、備份與複本的刪除／到期策略必須在上線前文件化；不能只刪除主資料列就宣稱資料已完全刪除。

## 5. 介面／API 定義

API 前綴：`/api/v1`。JSON 使用 UTF-8；日期時間採 ISO-8601。所有公開 GET 僅回傳已發布資料。錯誤格式統一：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "請檢查表單欄位。",
    "fields": {"email": "請輸入有效的電子郵件。"},
    "request_id": "req_..."
  }
}
```

### 5.1 `GET /api/v1/products`

取得公開四階產品摘要。

**Query**

- `locale`: `zh-TW` 或 `en`，預設 `zh-TW`。

**200 輸出**

```json
{
  "items": [
    {
      "id": "tier-1",
      "tier": 1,
      "slug": "entry-retreat",
      "title": "《心靈樹洞》AI 盲聊秘境微旅",
      "summary": "...",
      "application_mode": "PUBLIC",
      "offerings": [
        {"code": "DOMESTIC", "location": "宜蘭礁溪等國內場", "price_twd": 48000, "price_unit": "PER_PERSON"}
      ]
    }
  ]
}
```

錯誤：`400 INVALID_LOCALE`；`500 INTERNAL_ERROR`。

### 5.2 `GET /api/v1/sessions`

列出已發布且可見場次。

**Query**：`product_id` 選填、`locale` 選填。

**200 輸出**

```json
{
  "items": [
    {
      "id": "sess_...",
      "product_id": "tier-1",
      "starts_at": "2027-03-12T19:00:00+08:00",
      "ends_at": "2027-03-14T18:00:00+08:00",
      "location": "宜蘭礁溪",
      "price_twd": 48000,
      "status": "OPEN",
      "application_available": true
    }
  ]
}
```

`WAITLIST` 場次的 `application_available` 為 `true`；`CLOSED`／`CANCELLED` 為 `false`。

錯誤：`400 INVALID_PRODUCT_ID`；`500 INTERNAL_ERROR`。

### 5.3 `POST /api/v1/applications`

建立前三階場次申請。不得接受第四階產品或不存在／未發布場次。

**Request**

```json
{
  "session_id": "sess_...",
  "full_name": "王小明",
  "email": "user@example.com",
  "phone": "+886900000000",
  "age_years": 38,
  "occupation_category": "technology",
  "education_text": "（完整填寫教育與經歷；佐證文件後續補交）",
  "motivation": "希望深入交流價值觀。",
  "adult_single_declaration": true,
  "safety_policy_accepted": true,
  "privacy_notice_version": "2026-01",
  "locale": "zh-TW"
}
```

**201 輸出**

```json
{
  "application_id": "app_...",
  "status": "RECEIVED",
  "message": "申請已收到，主辦方確認後將再聯絡您。網站尚未收款。",
  "email_status": "QUEUED"
}
```

對 `WAITLIST` 場次回傳 `status: WAITLIST`，訊息須說明候補由主辦方人工挑選且不保證遞補。

**錯誤**

- `400 VALIDATION_ERROR`：缺欄、格式錯誤、同意未勾選或無效語言。
- `404 SESSION_NOT_FOUND`：場次不存在或未發布。
- `409 APPLICATION_CLOSED`：場次為 `CLOSED` 或 `CANCELLED`。
- `409 PRODUCT_NOT_APPLICABLE`：產品屬第四階邀請制。
- `413 REQUEST_TOO_LARGE`：請求超過限制。
- `429 RATE_LIMITED`：請求頻率超限。
- `500 INTERNAL_ERROR`：未預期錯誤；回應不可包含個人資料或 SQL 內容。

### 5.4 `GET /api/v1/health`

供部署檢查，不回傳資料庫路徑、版本機密或個資。資料庫不可用時回傳 `503 SERVICE_UNAVAILABLE`。

### 5.5 內部操作

首版不提供產品／場次管理、申請查詢、狀態更新或 CRM API。產品與場次由受控部署種子資料／管理者維護流程更新；申請資料使用受限營運信箱或經核准的安全收件方式處理。若日後要新增內部 API，必須先規劃管理員登入、MFA、RBAC、稽核紀錄及資料匯出控管。

## 6. 流程與邊界條件

### 6.1 正常申請流程

1. 前端載入所選語言的公開產品及可申請場次。
2. 使用者選擇第一至第三階的場次並閱讀活動、隱私及安全說明。
3. 使用者填寫表單、勾選聲明並送出。
4. Python API 驗證場次、產品階段、欄位格式、必需同意及場次狀態。
5. API 在單一 SQLite transaction 內建立申請、同意記錄及 email outbox 記錄。
6. API 回傳申請編號與 `RECEIVED`／`WAITLIST` 狀態。
7. 背景寄信工作者讀取 outbox，發送對應語言確認信並更新寄送狀態。
8. 主辦方在網站外依核准的人工流程聯絡申請者安排後續確認及付款。

### 6.2 例外與邊界

- **場次狀態競爭：** 建立申請時再次查 DB 狀態；已關閉則拒絕，若轉為候補則以候補狀態建立。
- **重複送出：** 前端提交期間停用按鈕；API 支援 `Idempotency-Key`。同一 key 重送回傳原申請結果，不新增重複紀錄。
- **資料庫寫入失敗：** rollback transaction，回傳 503/500，不回報成功，不寄信。
- **寄信服務失敗：** 保留申請與 outbox，重試採退避策略；達重試上限後標為 `FAILED` 並觸發營運告警。前端仍顯示申請已保存。
- **資料庫 busy／併發：** 設定合理 busy timeout；對短暫鎖定有限重試，超限回 503 並提供重試提示。
- **垃圾申請：** 限制 IP／網段速率、請求大小及欄位長度；是否使用 CAPTCHA 待產品決策，不得造成無障礙障礙。
- **中英文缺翻譯：** 不以空字串發布；回退至繁中前，須確認使用者可辨識語言且不掩蓋必要契約資訊。
- **第四階直接呼叫 API：** 伺服器檢查產品申請模式並拒絕，不依賴前端隱藏按鈕。
- **個資保存到期：** 排程需依核准政策執行並留存不含申請內容的刪除作業稽核；備份到期策略一併落實。
- **第三階拍攝規則未決：** 不建立肖像授權欄位或將拍攝同意混入一般活動申請；拍攝特別場另案規格。

## 7. 驗收標準

### 7.1 產品展示

- AC-001：繁中與英文均能呈現四階產品名稱、地點／形式、行程節奏、價格單位及團隊配置。
- AC-002：第四階清楚標為邀請／審核制，頁面沒有一般申請表或一般報名 CTA。
- AC-003：未核准場次日期、費用包含項目或旅行契約資訊不會被呈現為確定承諾。
- AC-004：產品頁不承諾配對、錄取或關係結果。

### 7.2 場次與申請

- AC-010：`OPEN` 場次允許申請，`WAITLIST` 場次允許申請並顯示候補，`CLOSED`／`CANCELLED` 場次拒絕申請。
- AC-011：API 不允許第四階、未發布或不存在場次建立申請。
- AC-012：缺必要欄位、格式錯誤、聲明未勾選或安全公約未同意時，API 回傳欄位錯誤且不寫入申請資料。
- AC-013：申請成功時只建立一筆申請及對應同意／寄信佇列資料，回傳可追蹤的申請編號。
- AC-014：候補申請的成功頁及郵件均明確說明候補、人工挑選及不保證遞補。
- AC-015：成功頁及確認信明確表示申請已收到、尚待主辦方確認、網站未收款。
- AC-016：郵件暫時失敗不會遺失已保存申請，且 UI 不會表示郵件已寄達。
- AC-017：申請表及 API 不收集收入、資產負債、戶籍或財力／婚姻驗證結果。

### 7.3 安全、資料與雙語

- AC-020：未授權訪客不能讀取、修改、列出已提交申請。
- AC-021：日誌、錯誤回應及分析事件不包含完整聯絡資料或動機內容。
- AC-022：資料庫外鍵啟用、交易回滾正確，寄信 outbox 可重試且避免重複申請。
- AC-023：資料刪除排程、備份到期和例外政策有文件並可稽核；180 天起算規則尚未核准時，不得宣稱此條件已達成。
- AC-024：主要流程可用鍵盤完成，表單欄位具標籤、錯誤提示及窄螢幕版面。

## 8. 技術棧／限制

### 8.1 建議架構

- **前端：** React + TypeScript；以 React Router 或等效路由管理頁面；雙語字串集中管理。
- **後端：** Python 3.12+；建議 FastAPI 提供 REST API、Pydantic 驗證 request/response、SQLAlchemy 2.x 或 sqlite3 存取資料。
- **資料庫：** SQLite；使用 migration 工具（例如 Alembic）管理 schema 版本；外鍵、交易及備份策略必須啟用／文件化。
- **寄信：** SMTP 或受控交易郵件供應商；使用 outbox worker，金鑰存於環境變數／密鑰管理服務，不入庫或原始碼。
- **部署：** React 靜態資產由同源反向代理提供，API `/api/v1`；生產資料庫放在持久化、非公開磁碟。

### 8.2 限制與設計注意

- PRD 未指定主機、寄信供應商、申請收件負責人或管理資料的方式；上線前須決策。
- SQLite 適合首版低至中等寫入量與單一主要資料庫節點；需配置 WAL（若部署型態適用）、備份、busy timeout、磁碟容量監控。需要多節點高併發時需重新評估資料庫選型。
- 首版沒有管理後台，因此場次更新流程必須受控；不應要求營運人員直接以不安全方式編輯生產 SQLite 檔案。可採經審核的部署資料更新或另立安全管理後台規格。
- 會員中心、AI 報告、CRM、節目海選資料庫隔離、Deal-breakers 自動篩選均不在本版實作範圍。後續如啟動，須新增帳號認證、RBAC／MFA、稽核日誌、權限隔離與專屬資料生命週期規格。
- 「物理隔離」、「絕對隱私」、AI 相容度或心理診斷等對外承諾，只有在技術與營運控制實際驗證後方可發布。

## 9. 待定事項與開發阻擋項

以下內容未定前，相關功能不得視為可上線：

1. 實際場次日期、名額、地點、價格、包含／不包含項目與取消／退款條款。
2. 年齡採精確歲數；電話是否必填、學經歷文字長度及動機字數待定。學經歷佐證文件後續補件的欄位、端點、檔案類型、大小、期限與保存策略待決。
3. 個資告知、同意文字版本、保存期限例外、180 天起算點、刪除及備份期限。
4. 申請資料的營運收件方式、資料存取人員及郵件服務供應商。

6. 英文譯文核稿人及海外行程相關旅行社／契約資訊。
7. 若採 SQLite 生產部署，磁碟持久化、備份／復原、加密與部署拓樸。
